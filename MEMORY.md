## Live work — 2026-07-29 (bottom-sheet overlay polish + commit)
Founder UI polish on the Logbook "ADD" shelf, all shared through one reusable control, deployed to **all three targets** (Android emulator, iOS sim, physical iPhone 17 Air):
- **Reusable sheet architecture.** The add + streaming-sync sheets are one `Controls/BottomSheet` hosted in a `Controls/TransparentModalPage` (see `Pages/SheetOverlayPage`) pushed OVER the whole window — so each card overlays the Shell tab bar with the menu dimmed *underneath* (a page-hosted sheet can't: the tab bar sits below it on Android / floats over it on iOS). Reaches the true device bottom on both platforms (iOS negative-margin bleed past the safe-area inset; Android consumes window insets in `TransparentModalPage` so MAUI doesn't shrink the modal into the nav bar).
- **Native frosted backdrop** (`Controls/BlurView` + per-platform `BlurViewHandler`). iOS: live `UIVisualEffectView` scrubbed to partial intensity via a paused `UIViewPropertyAnimator` (`UIBlurEffectStyle.Dark` = black tint, not the grey `*MaterialDark`). Android has no live backdrop blur, so it snapshots the DecorView and applies a hardware gaussian `RenderEffect.CreateBlurEffect` (API 31+; downscale/upscale fallback pre-31) — smooth, matching iOS. A black `#59000000` scrim over both keeps the frost black while content stays softly visible.
- **Removed** the sonar sync button from the top-right of every page (the shelf carries that action now) and the "Connect your computer or dive center" empty-state CTA.
- **Header re-render fix.** Closing the shelf replayed `TrimixPage`'s `screenIn` entrance on the Logbook (header "slid back in") because `OnAppearing` re-fires when the transparent modal pops. Fix: `TrimixPage.SuppressNextScreenIn()` (opt-in, one-shot) + a `_returningFromOverlay` guard in `LogbookPage` — the overlay round-trip skips both the entrance and the redundant `LoadCommand` reload (the page never left the screen; a sync reloads itself in `OnSyncPropertyChanged`).
- **Shelf slide doubled in speed** (founder: "half as long", across the board). `BottomSheet` `SlideMs 380→190`, `ScrimMs 300→150`, drag spring-back `180→90`. One control ⇒ both sheets app-wide.
- Evidence: 343/343 Core tests green; Android + iOS TFMs both build 0 errors; header-fix behaviour live-verified on Android (header pixel-stable pre-open vs post-close), smooth Android blur screenshot-confirmed.

## Gotchas
- **iCloud mount — commit + push promptly.** The whole tree lives on the iCloud Drive path, where an eviction can strip locally-present files. Everything through `750ba82` is pushed (see Watch list), but any new uncommitted work is one eviction from loss. Run `repo-durability-check` before asserting git safety.
- **No CI.** Every "green" rests on a local `dotnet build`/`test` on one Mac with the user-local toolchain. Never mark a gate met on that basis.
- **Connectors are fixture-validated only.** No live vendor server was ever touched. Endpoints (Garmin SSO, Suunto `/v1`, Oceanic+, MySSI for Mares/ScubaPro/SSI, PADI GraphQL) are **researched-guess defaults**, config-injectable, and will likely need real endpoints at first live contact. Garmin's unofficial path (`garth`) died March 2026; `python-garminconnect`-style Android SSO is the surviving reverse-eng route. **No connector has ever imported a real dive.**
- **On-device entitlements are piratable** (no server receipt validation) — the accepted serverless tradeoff.
- **The community-atlas "N divers logged here" counters are bundled seed facts, not live data** — the serverless model has no shared DB.
- **Dive-row push destinations reflect *currently linked* push providers**, not a per-dive push ledger (same approximation the prototype makes).
