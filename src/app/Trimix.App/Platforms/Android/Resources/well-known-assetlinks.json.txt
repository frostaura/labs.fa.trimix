REFERENCE TEMPLATE — Android Digital Asset Links (assetlinks.json)
==================================================================

This is a REFERENCE ONLY, not a build artifact. Android's Credential Manager will only create or
use platform passkeys for this app once the relying-party (RP) domain publishes a Digital Asset
Links statement that vouches for the app's signing certificate. Until that is hosted and the
fingerprint below is real, Auth.PasskeyAuthService is code-complete but cannot be exercised at
runtime (no emulator/localhost passkeys) — this is the M3-style device/domain-dependent gate.

HOW TO USE
----------
1. Get the SHA-256 fingerprint of the certificate that SIGNS the shipped APK/AAB. For Play-signed
   builds use the "App signing key certificate" SHA-256 from Play Console > Setup > App integrity.
   Locally:  keytool -list -v -keystore <your.keystore> -alias <alias>
   The fingerprint is the colon-separated uppercase hex string (e.g. AB:CD:...:EF).
2. Replace PLACEHOLDER_SHA256_FINGERPRINT below with that exact value. Multiple fingerprints
   (upload key + Play app-signing key, or debug + release) may be listed in the array.
3. Host the finished JSON, byte-for-byte and with Content-Type: application/json, at:
       https://<relying-party-domain>/.well-known/assetlinks.json
   The <relying-party-domain> MUST equal the WebAuthn "rp.id" the backend puts in the options JSON.
4. Verify:  https://developers.google.com/digital-asset-links/tools/generator

FINISHED FILE CONTENTS (copy the JSON below into assetlinks.json on the RP domain):

[
  {
    "relation": [
      "delegate_permission/common.get_login_creds",
      "delegate_permission/common.handle_all_urls"
    ],
    "target": {
      "namespace": "android_app",
      "package_name": "net.frostaura.trimix",
      "sha256_cert_fingerprints": [
        "PLACEHOLDER_SHA256_FINGERPRINT"
      ]
    }
  }
]
