# labs.fa.trimix — Trimix (working name)

## Research question
Gaia bet APP-03, three gates in order. **(1)** Does a FREE community demo, seeded through `Underwater/`/OceanCare and r/scuba channels, produce ≥300 organic activated divers (≥1 dive logged) — **before any paid spend**? **(2)** Among activated users shown the purchase moment, does install→payer conversion reach ≥3% at the locked one-off ladder ($14.99 Pro / $29.99 Lifetime, blended net per payer ≥$13)? **(3)** Can ≥2 of the read slate (Garmin, Suunto, ScubaPro, Mares, Oceanic+, Shearwater; PADI and SSI are *push* targets, not read corridors) be integrated and imported reliably via **API/cloud sync** in real post-dive field conditions? **The product is API-sync-only** — there is no BLE path. No vendor exposes a usable public dive API, so every integration is an on-device reverse-engineered private-cloud client; gate-3's "integrated *legally*" is a knowingly-accepted ToS/CFAA risk (see the legal override in [`memory/decisions.md`](memory/decisions.md)). Which providers are actually live at any moment is `ProviderCatalog.LiveConnectorIds`, and its current contents are recorded in [`memory/state.md`](memory/state.md), never here.

## What this program is
A scuba dive log that fills itself, **serverless and on-device**: *"No cloud, no servers — your logbook and links never leave this device."* It links each dive platform's cloud directly from the phone (per-user OAuth/credential), pulls the diver's own dives in, normalizes them to one canonical dive, shows Oceanic+-grade stats, and pushes back out to certification logbooks (PADI, SSI). Core loop: dive → sync → reflect → return richer. **Trimix is a logbook + sync tool and nothing else — there is no Sites capability** (no bundled site atlas, no Sites tab, no dive-site enrichment or auto-match); it was removed by founder direction and re-adding it needs explicit founder sign-off. Monetization is a single designed purchase moment at the free-tier import cap. This remains **the heaviest-build, thinnest-TAM bet in the Gaia slate** — the free community-demand gate exists to kill it cheaply.

## Stack & repo
The repository is `frostaura/labs.fa.trimix` on GitHub; this directory is one clone of it, kept as the context-file home, and the dev clone is **`~/src/labs.fa.trimix`**, outside iCloud per the founder's develop-outside-iCloud rule. Visibility and durability are state ([`MEMORY.md`](MEMORY.md)); name clearance still gates the store listing and any public domain. Solution `labs.fa.trimix.slnx` at root, **four projects, no backend**: MAUI client under `src/app` (`Trimix.App` + `Trimix.Core`), shared contracts under `src/shared` (`Trimix.Contracts`), and the test project under a top-level `tests/` (`Trimix.Core.Tests`). A fifth `.csproj` exists on disk and is **deliberately not a member of the solution** — the dev-only console harness under `src/tools` (`Trimix.Harness`). A solution-level build therefore never compiles it: build or run it by its own project path, and treat it as code nothing routine exercises.

- **`src/tools/Trimix.Harness` is not shipped.** It references `Trimix.Core` and drives a real connector against a live vendor API in seconds, so a login → token → list → fetch flow can be iterated without a MAUI deploy. `TRIMIX_MODE=connector` runs the real `GarminCloudSourceConnector`; `TRIMIX_MODE=scubapro` runs `ScubaProCloudSourceConnector`; the default mode probes raw endpoints (commands under *Build / test / run*). Read-only: it only ever GETs dives. See the contracts under `docs/reverse-engineering/` — **that directory and the harness are the least reproducible artifacts in the repo; check `MEMORY.md` for their durability status before assuming they are safe.** The `Trimix.Api` backend, EF Core, PostgreSQL, docker-compose and `tests/Trimix.Api.Tests` do not exist — they were deleted in the serverless pivot and are not coming back.

- **Client: .NET MAUI**, C# end to end, one codebase for both stores. A documented, root-reviewed stack override (the React mandate cannot ship a native store app). **Android is the default target; `net10.0-ios` is opt-in behind `-p:EnableIos=true` and must keep compiling.**
- **No server.** Accounts, server-authoritative entitlements, the shared/moderated site DB, server dive-sync, and the analytics ingest server are gone. Entitlements are **on-device** (StoreKit / Play Billing → local grant); the funnel taxonomy fires to a **local analytics sink**, with no ingest server anywhere.
- **Connector layer** is the reusable seam (`Trimix.Core/Abstractions/IDiveSourceConnector.cs`): the on-device reverse-engineered private-cloud clients under `Connectors/Cloud/` register against it, and `ProviderCatalog` decides which of them a user can actually connect. Tokens live in iOS Keychain / Android Keystore (`Connectors/Infra/ISecureTokenStore`). **Backends differ per vendor and every shared-corridor assumption made so far has been wrong — verify by capture, never by inference.** Three infrastructure clients exist behind the seam and are the reusable part: `FirebaseCloudClient.cs` (Firebase Auth + Firestore, parametrized by a `FirebaseAppConfig`, so a second Firebase-backed vendor is a config not a client), `MySsiCloudClient.cs` and `HttpClientTransport.cs`. SSI and PADI are *push* targets, not read corridors. `DiveComputer/SyncCoordinator.cs` is the "Sync now" entry point over `ImportService.ImportFromConnectorAsync`. **Which vendor sits on which backend, and which have been confirmed against a live server, is state — it lives in `MEMORY.md` and in `docs/reverse-engineering/`, not here.**
- **Rails-first (binding):** the analytics event taxonomy and the entitlement pipeline are built and test-verified before feature work. Entitlements are on-device and survive reinstall via store restore (**client-trust — piratable; an accepted serverless tradeoff**).
- **Quality bar: Silver (adapted for mobile).** Store deployment is out of scope until Stage-7 compliance and name clearance.

## Conventions & invariants
- **The funnel event taxonomy is frozen.** Names are additive-only and never renamed. The serverless pivot and later removals left several events **retained-but-no-longer-emitted** (`ble_*`, `dive_logged_manual`, `dives_fetched`, all `site_*` — `site_viewed` / `site_contribution_*` / the `site_matched_bool` and `site_id` props — and the former server-only `account_created`) — the constants stay; no name was deleted. Events now fire to a local sink; there is no ingest server. `entitlement_granted` is emitted on-device by `EntitlementService`.
- **We log dives; we do not compute deco.** Displaying imported NDL/ceiling/CNS and the Nitrox MOD planner is data/display math, not tissue-loading computation. Permanent liability non-goal.
- **Non-goals:** no auto-renew ever, no loot-box/gacha, no ads, no deco engine, no social feed, **no backend/server** (serverless is now a product invariant), **API-sync-only import** (no BLE, no file import/export, no manual entry, no HealthKit), no web app.
- **SKUs are a locked ladder:** `trimix.pro` $14.99 and `trimix.lifetime` $29.99 — exactly two, both true non-consumables, no auto-renew. **The free tier keeps a fixed number of most-recent dives and the next one fires the paywall** — the number is the `FreeTier` constants and nothing else. Copy binds to the constant, never a hardcoded number.
- **No auth of any kind — the phone IS the account.** There is no sign-in, no biometric unlock, no accounts, no passkeys, no email/OAuth for Trimix itself, and the app is never locked at launch. `IAuthSession`, `IBiometricUnlock`, `AuthPage`/`AuthViewModel` and the account UI do not exist — the founder removed them for bare-minimum cognitive load (the superseded auth decisions are in `memory/decisions.md`). Onboarding is kept and is re-runnable from Settings ("Replay onboarding", data-preserving) alongside a "Reset app" factory reset. **Vendor** OAuth for connectors (`ProviderOAuthViewModel`, PADI/SSI/Garmin credential exchange) is unrelated and stays.
- **Text inputs, haptics and the entry-point map are platform-divergent BY DESIGN — do not "unify" any of the three.** Android inputs are Material filled fields; iOS inputs are borderless inside the outlined GlassCard. Haptics go through Core's `IHaptics` mapped to each OS's native feedback API — never MAUI Essentials' `HapticFeedback` — and fire on the intent, not on completion. The entry-point map is a live MapKit view on iOS and a hand-off to the Google Maps app on Android; the Maps package is referenced only for iOS TFMs. Why each is that way, and the passes that broke them: [`memory/decisions-ui.md`](memory/decisions-ui.md), [`memory/decisions-haptics.md`](memory/decisions-haptics.md).
- **Anything interactive nested inside a `ScrollView` must claim the touch stream on touch-down and release it on BOTH the end and the cancel path.** This applies to the chart scrub and the embedded map today, and to whatever is added next. Android: `RequestDisallowInterceptTouchEvent`. iOS: `UIScrollView.ScrollEnabled = false`. Disabling the child instead (the map originally shipped inert) is a workaround the founder has explicitly rejected.
- **`docs/reverse-engineering/` is the contract, and a captured contract outranks any code comment.** Every vendor whose corridor has been established has a document there; connector fixtures are copied from that document, and **a fixture that drifts from its doc is a bug in the fixture, never the other way round.** A vendor with no document there has not been verified, whatever the connector claims. Garmin's 1 Hz JSON columnar profile block is read **by key, never by index**. Which backend each vendor rides, and its load-bearing traps, are state: `memory/decisions-connectors.md`, `memory/gotchas-connectors.md`, `memory/gotchas-firebase.md`.
- **Reverse-engineered connector guardrails (do NOT relax, independent of the legal override):** (i) never persist a vendor password in plaintext — ephemeral exchange → token in Keychain/Keystore; (ii) per-user opt-in behind a plain-language ToS-risk disclosure shown *before* consent; (iii) truthful labelling — "user-assisted personal export", **never** "official <Vendor> integration". Every `ToSRiskReverseEng` descriptor ships `EnabledByDefault=false`; connectors are *registered/visible by default* and gated by the per-user consent store, so availability comes from consent, not from flipping that flag. **The "never exercise a real vendor server" rule carries one standing founder carve-out: read-only ingestion of the founder's own dives, hand-driven.** Which vendors have actually been exercised under it is state — [`memory/gotchas-connectors.md`](memory/gotchas-connectors.md).
- **Design:** palette tokens live in `src/app/Trimix.App/Resources/Styles/Colors.xaml` — mint `Sonar` `#2FE3C4` on `Abyss` `#0A1013`; Space Grotesk 700 headings, JetBrains Mono numerals/eyebrows, Hanken Grotesk body; forced dark; **2-tab bar (Log · You)** — there is no Sites tab and no account step. [`docs/design/mockup-spec.md`](docs/design/mockup-spec.md) is the design reference, but **code is authoritative wherever it and the spec conflict** (how far the spec has drifted: `memory/watch-docs.md`).

## Build / test / run
Toolchain is the **user-local `~/.dotnet`** (`DOTNET_ROOT=$HOME/.dotnet`; no `global.json` pins the SDK — the division's `maui-device-build` skill covers why the system dotnet is out). Android build also needs `JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home` and `ANDROID_HOME=$HOME/Library/Android/sdk` (**OpenJDK 17**, Android SDK API 36).
- `dotnet build src/app/Trimix.Core/Trimix.Core.csproj` (plain `net10.0`).
- `dotnet test tests/Trimix.Core.Tests/Trimix.Core.Tests.csproj` — must be fully green before any claim of "done". **Never write a test count into any context file here** — green-or-not is the signal and the number moves with the next commit; the suite's status lives in [`MEMORY.md`](MEMORY.md), not here.
- `dotnet build src/app/Trimix.App/Trimix.App.csproj -f net10.0-android` (default) or `-f net10.0-ios -p:EnableIos=true`. Add `-p:EmbedAssembliesIntoApk=true` to the Android build — **mandatory when deploying to a device or emulator.** Without it, Debug builds keep assemblies outside the APK and `adb install` runs the PREVIOUS managed code.
- Harness (Garmin): `TRIMIX_MODE=connector GARMIN_USERNAME=… GARMIN_PASSWORD=… TRIMIX_TOKEN_CACHE=/tmp/tok.json dotnet run --project src/tools/Trimix.Harness/Trimix.Harness.csproj` (the token cache avoids the sign-in rate limit). ScubaPro: `TRIMIX_MODE=scubapro LOGTRAK_USERNAME=… LOGTRAK_PASSWORD=…` — or seed the cache with a captured refresh-token envelope to skip sign-in entirely.

Real StoreKit/Play Billing and the vendor cloud endpoints are **runtime-gated** — they need a device, a real store account, and config-injectable vendor endpoints. `docs/known-gaps.md` is the catalogue.

## Blocking gates that are not code
**Name clearance** transitively gates the store listing and any public domain; whether it has been run is state — [`MEMORY.md`](MEMORY.md). **Vendor endpoints** — a connector whose corridor has no document under `docs/reverse-engineering/` is running on a researched *guess* validated only against a fixture it invented; treat it as unimplemented until a capture says otherwise, and check `MEMORY.md` for which ones those are.

## Never do this here
- Never rename or delete a funnel event constant (frozen taxonomy).
- Never ship a deco/tissue-loading calculation.
- Never label a reverse-engineered connector as an official vendor integration, persist a vendor password in plaintext, or show consent before its disclosure.
- Never exercise a connector against a real vendor production server **beyond read-only ingestion of the founder's own dives** — that narrow carve-out is the standing founder reversal recorded above. Writing to a vendor, touching another person's account, or any volume beyond hand-driven iteration is out.
- Never re-add a backend, BLE, file import/export, manual entry, HealthKit, the Sites capability, or any form of app auth/accounts/biometric-unlock without explicit founder sign-off — each removal was a founder decision, not incidental. (Vendor connector OAuth is separate and stays.)
- Never leave a live vendor capture on disk. A mitmproxy flow file from a vendor login holds the founder's password and session key in plaintext — sweep for `*.mitm` and securely delete every capture the moment its contract is banked.

## Upkeep

This file, `MEMORY.md`, its `memory/` topic store, and the skills that fire at this level are kept current **as changes land**, not in a later cleanup pass. `MEMORY.md` is required here exactly as this file is, and it cascades downward on identical terms — an instruction file with no `MEMORY.md` beside it is a defect, not a shortcut: the rules are stated and reality is left unstated, so the next agent infers status instead of reading it. Both files, or neither.

- **Memory — always.** Update the topic files at the end of any session that shipped, decided, discovered, abandoned or unblocked something; re-cut the `description:` of any topic whose signal moved, then regenerate `MEMORY.md` from the topic files rather than editing it — `python3 .claude/scripts/audit-tree.py --no-git --fix-index --scope Labs/projects/labs.fa.trimix` from the tree root; restamp `last_verified:` only for what you actually re-inspected. Record decisions *with their why* — a decision without its rationale is reversed by the next agent, who sees only its cost.
- **This file — only when a rule changed.** A new convention, command or invariant earns an edit. A status change does not; it belongs in the memory store.
- **Skills — when *how* the work is done changed.** Fix or delete a skill whose commands or thresholds no longer exist; a stale skill is worse than a missing one because it fires with authority. A procedure that would be correct in a repository with nothing to do with this tree belongs upstream in a plugin, never forked into this tree.
- **Scratch — always.** Empty `.tmp/` before the session ends, promoting anything that still mattered first.

None of these four are assessed by search. Read the scope's files end to end before changing any of them. Drift is not caused by neglect over months; it is caused by good sessions that ended without a close-out.
